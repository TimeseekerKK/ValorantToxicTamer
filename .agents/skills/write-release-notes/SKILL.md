# 撰写 Release notes

为本仓库的 Release 正文撰写简洁的简体中文修改说明，正式版与 Beta 使用相同的正文规则。与 `review-and-bump-version` 配合时，由该技能负责版本、构建和发布，本技能负责正文。

## 内容范围

- 根据本次已确认的改动、相关 diff 和必要的源码上下文，说明实际完成的新增、修复、优化或调整。不把计划、推测和无关历史改动写成本次成果；改写旧说明时同样核对事实。
- 直接写“改了什么”及必要的用户影响。每条聚焦一项改动，合并重复内容，避免逐条照抄提交记录、堆砌内部实现或使用“全面提升体验”等空话。
- 正文保留修改内容叙述及下方要求的下载文件说明。不另列完整版本、发布渠道、来源分支、源码提交 SHA 或链接、验证或测试说明，以及这些字段对应的标题和占位文字。不改成同义字段，也不把它们挪到脚注或折叠区；下载说明中的实际附件名可保留完整版本号。
- 不附加发布信息表、构建记录、校验值、无关下载教程或自动生成的完整提交对比链接。Release 的标题、标签、预发布标记和附件仍由发布流程设置；标题与完整标签一致，Beta 保留 `-beta.N`，正文不重复这些元数据。
- 验证信息用于判断描述是否有依据，不能因正文省略验证而把未确认的效果写成已完成或已解决。

## 下载文件说明

- 正式版与 Beta 的 Release notes 均须简短说明安装包与免安装版的区别，放在修改内容之后。
- `ValorantToxicTamer-Setup-v<完整版本号>.exe`：安装包，运行后进入安装向导，可选择安装位置，并支持卸载。
- `ValorantToxicTamer.exe`：免安装版，下载后可直接运行；移动时应同时移动同目录的 `data` 文件夹。
- 提醒免安装版用户：使用应用内自动更新也会进入安装流程，完成后按安装版管理。
- 根据本次实际附件填写安装包名称；历史 Release 缺少某种附件时，不引导用户下载不存在的文件。核对该版本的更新行为，仅在其支持上述安装包更新流程时使用对应提醒。

## 输出形式

修改内容优先直接输出简短的 Markdown 列表，不另加版本标题、开场白或总结。改动较多时可按“新增”“修复”“优化”等实际内容分组，省略空组；仅有一项改动时可用一句话。之后附上简短的“下载说明”。

示例（仅示范写法，不代表本次已实现）：

```markdown
- 新增语录搜索，支持按关键词筛选内容。
- 修复切换语录库后列表未刷新的问题。
- 调整设置页布局，让快捷键配置更易查找。

### 下载说明

- `ValorantToxicTamer-Setup-v<完整版本号>.exe`：安装包，可选择安装位置，支持卸载。
- `ValorantToxicTamer.exe`：免安装版，直接运行即可；移动时请一并移动同目录的 `data` 文件夹。使用应用内自动更新后会转为安装版。
```

交付前核对每条描述与实际改动一致、下载说明与实际附件及更新行为一致，确认没有遗留附件名占位符，且正文没有另列版本、分支、提交或验证字段。只请求文案时直接交付正文；发布任务中将该正文交给现有发布流程，不因加载本技能自行创建或修改远端 Release。
