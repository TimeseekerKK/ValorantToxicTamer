# ValorantToxicTamer

**Valorant 反嘴臭工具 · Windows 托盘快捷消息助手**

把常用消息整理到本地列表，在游戏中按快捷键发送到队伍或全体聊天。支持中文输入、消息搜索、TXT 导入导出，以及正式版 / Beta 双渠道更新。

**运行平台：** Windows 10 / 11　·　**当前源码版本：** `v1.6.0`

[下载程序](https://github.com/TimeseekerKK/ValorantToxicTamer/releases) · [快速开始](#快速开始) · [技术栈](#技术栈) · [使用方法](#使用方法) · [项目原理](#项目原理) · [项目结构与开发](#项目结构与开发) · [免责声明](#免责声明) · [许可证](#许可证)

> 初始消息列表为空，不附带语录库。首次使用请自行添加消息，或导入个人 TXT 文件。

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 双频道快捷发送 | 默认 **F8** 发送到队伍、**F9** 发送到全体；两个频道共用列表，按顺序循环 |
| 个人消息管理 | 添加、编辑、删除、清空、排序和搜索；长消息可滚动预览，修改自动保存 |
| TXT 导入导出 | 每行一条消息，支持导入预览、可选去重、备份与迁移 |
| 托盘常驻 | 默认隐藏到托盘；支持自定义快捷键、字号、发送冷却和开机启动 |
| 应用内更新 | 可选择正式版或 Beta 渠道，支持下载进度、取消检查 / 下载和覆盖更新 |

## 快速开始

1. 前往 [Releases](https://github.com/TimeseekerKK/ValorantToxicTamer/releases)，选择所需版本，下载附件中的 `ValorantToxicTamer-v<完整版本号>.exe`。
2. 双击 EXE，在 Windows 管理员权限提示中选择「是」。**打包版无需安装 Python 或依赖。**
3. 双击任务栏右下角的托盘图标，打开「消息管理」，添加消息或使用「TXT 导入」。
4. 切回 Valorant，关闭聊天框并松开 Shift / Ctrl / Alt / Win，按 **F8** 或 **F9** 发送。

默认发送冷却为 **0.5 秒**，长按不会连发。关闭主窗口后程序继续在托盘运行；完全退出请右键托盘图标，选择「退出程序」。

## 使用方法

### 运行环境

| 使用方式 | 需要准备 |
| --- | --- |
| 下载 EXE 直接运行 | Windows 10 / 11，允许启动时的管理员权限请求 |
| 从源码运行 | Windows 10 / 11、Python 3.11，以及 `requirements.txt` 中的依赖 |
| 构建 EXE | 在源码环境中额外安装 `requirements-build.txt`，通过 PowerShell 执行构建脚本 |

### 1. 启动程序

**使用打包版：** 在 [Releases](https://github.com/TimeseekerKK/ValorantToxicTamer/releases) 下载所需版本的 EXE 并双击启动。正常启动时默认请求管理员权限，请在 Windows 用户账户控制（UAC）提示中选择「是」；拒绝授权则退出。已经以管理员身份运行时直接启动，不重复请求。

**从源码运行：** 先下载并解压本仓库源码，安装 Python 3.11，然后在包含 `main.py` 的项目根目录打开 PowerShell，执行：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\pythonw.exe main.py
```

前两条命令只需在首次准备环境时执行，之后运行第三条即可。源码启动同样默认请求管理员权限。如果 `py` 找不到已安装的 Python，请使用 Python 3.11 的 `python.exe` 完整路径执行第一条命令。

程序默认启动后隐藏到系统托盘。双击任务栏右下角的托盘图标打开主窗口；如果没看到图标，请展开隐藏图标区域。

### 2. 添加和管理消息

在主窗口的「消息管理」页操作：

- **添加**：输入一条单行消息并确认。
- **编辑**：选中消息后点击「编辑」，或直接双击消息。
- **删除**：选中消息，点击「删除」并确认。
- **清空列表**：一次删除全部消息，确认后自动保存且无法撤销；如需保留，请先导出 TXT 备份。列表为空或正在发送时不可用。
- **上移 / 下移**：调整消息的发送顺序。
- **TXT 导入**：从文本文件追加消息，每行一条，空行会被忽略。
- **TXT 导出**：将当前列表导出，方便备份或迁移。
- **搜索**：按消息内容筛选，忽略英文字母大小写；显示匹配条数，保留原序号，不改变发送顺序或进度。筛选期间不能上移、下移；清空搜索后可继续调整顺序。

所有消息更改自动保存。修改列表或重新启动程序后，循环从第一条开始；窗口上方的「下一条」显示接下来要发送的内容。选中列表中的某条消息用于编辑，不会改变发送顺序。

导入文件建议使用 UTF-8 编码，也支持 UTF-8 BOM 和 GB18030；导出文件为带 BOM 的 UTF-8。每条消息不能包含换行、制表符或控制字符。

导入文件在后台读取、校验，完成后显示非空消息数、重复条数和前 5 条内容预览。默认保留重复消息，也可勾选「跳过重复消息」；重复按完整内容比较，同时包含与现有列表重复和文件内重复的条目。确认后追加并自动保存，取消不会修改列表或发送进度。单个文件最大 8 MiB、单次最多导入 20000 条消息；超过限制请拆分导入。

导入读取和预览期间暂停消息修改；确认时会按当前列表重新去重。编辑已导入的长消息不会因输入框默认长度限制而截断内容。

### 3. 在游戏中发送

1. 添加好消息后，切回 Valorant，让游戏保持在前台。
2. **关闭游戏聊天框，并松开 Shift / Ctrl / Alt / Win。**
3. 按下对应快捷键，程序会打开聊天框、输入下一条消息并按 Enter 发送。

| 默认快捷键 | 聊天频道 | 操作 |
| --- | --- | --- |
| **F8** | 队伍 | 自动按 Enter 打开聊天并输入消息 |
| **F9** | 全体 | 自动按 Shift+Enter 打开聊天并输入消息 |

两个频道共用同一个消息列表和发送进度：例如先按 F8 使用第一条，再按 F9 就会使用第二条，到末尾后回到第一条。

默认发送冷却为 **0.5 秒**，从本次输入结束后开始计算。长按快捷键不会连续发送；输入期间或冷却期间再次按键会被忽略。发送过程中请保持游戏在前台，不要切换窗口或按住修饰键。

### 4. 调整设置与退出

打开主窗口的「设置」页，修改后点击 **保存设置**：

| 设置项 | 使用说明 |
| --- | --- |
| 队伍聊天快捷键 / 全体聊天快捷键 | 可选择 F1–F11，两个频道必须使用不同按键；遇到快捷键冲突时可在此更换 |
| 共用发送冷却 | 直接输入 0.2–2 秒之间的数值（如 `0.8`），点击保存后生效；无效数值会提示错误 |
| 字体大小 | 在「界面显示」中选择 9–16 px，默认 13 px，点击保存后生效；鼠标滚轮只滚动页面，不改变字号 |
| 启动后隐藏到系统托盘 | 默认勾选；取消后，下次启动会显示主窗口 |
| 随 Windows 登录自动启动 | 默认关闭，按需勾选并保存；登录启动时也需确认管理员权限请求；移动程序位置后需重新设置 |

主窗口默认大小为 1067 × 669（含标题栏和边框），首次打开时应用。长消息预览支持滚动查看全文。

关闭主窗口会隐藏到托盘，程序继续运行。需要完全退出时，右键托盘图标，选择 **退出程序**。

保存设置时只应用发生变化的项目；仅调整字号、冷却或启动选项时保留现有快捷键注册。未修改设置时，不重复写入配置或重绘字号。

### 5. 检查更新

在「设置」页的「版本与更新」中选择更新渠道，再点击 **检查更新**。渠道选择立即生效并自动保存，无需点击「保存设置」；滚轮只滚动页面，不会误切换渠道。

- **正式版 Release**：只接收正式版。正在使用 Beta 时，可以切回较旧的最新正式版；安装前会明确显示当前版本、目标版本及降级警告，默认选择「否」。
- **测试版 Beta**：接收正式版和 Beta 测试版，按版本号选择最高版本，不自动降级。测试功能可能尚不稳定。

按钮使用线条刷新图标，检查、下载和准备安装时显示旋转动画，并暂时锁定渠道选择，避免中途切换。程序会查询对应渠道的 GitHub Release，比较版本号并查找其中的 EXE。发现新版本后弹出「发现新版本,是否更新」：选择「否」保持当前程序继续运行；选择「是」则下载并校验文件，退出当前程序，覆盖原位置的 EXE，然后重新启动。仍在运行的同路径程序会被强制退出；消息和设置保留在原数据目录。

检查和下载期间可点击「取消更新」；下载时显示百分比、已下载大小和总大小。取消后删除本次临时下载，保留当前程序，并可重新检查。进入「准备安装」后不再提供取消，以免中断覆盖流程。退出程序会取消尚未完成的检查或下载，并在后台任务清理期间保持界面响应。

下载失败时保留当前版本；覆盖失败会显示错误并保留原文件，启动失败会尝试恢复旧 EXE。覆盖更新仅支持打包后的 Windows EXE，且程序所在目录须可写；源码运行不能覆盖 Python 解释器。仅在明确选择正式版渠道、从 Beta 切回正式版并确认后允许降级；其它更新不降级。

更新查询和下载使用 Windows 原生证书信任链，保持 HTTPS 证书与主机名校验。若仍提示证书校验失败，请检查系统日期时间、Windows 证书更新，以及代理或安全软件的 HTTPS 证书设置，然后重试。

默认使用正式版渠道。版本比较支持 `beta.N`，Beta 序号按整数比较，同基础号正式版高于 Beta。更新渠道单独保存在数据目录的 `update_settings.json`，不改变消息和已有设置文件的格式，便于切回旧正式版。

更新渠道文件损坏或无法读取时，程序暂用正式版渠道，消息管理和快捷发送仍可使用，原文件不会自动覆盖。在设置页点击「恢复更新设置」，或重新选择渠道，会先将原文件备份为同目录的 `update_settings.invalid-*.json`，再保存渠道；备份或保存失败时会提示错误并保留原文件。

正式发布时使用 `v1.2.3` 形式的版本标签，Beta 使用 `v1.2.3-beta.1`；同步修改 `valorant_toxic_tamer/app_version.py` 中的 `VERSION`，并上传单文件 `ValorantToxicTamer-v<完整版本号>.exe`，保留 `-beta.N` 后缀。每个 Release 只上传一个程序 EXE，更新器支持这种附件名称。通过 `scripts/build.ps1` 打包时会自动读取 `VERSION` 生成文件名，并一并包含独立更新脚本和证书验证依赖。自动更新覆盖原路径的 EXE，保留原文件名。

### 常见问题

**按快捷键没有反应怎么办？**

打开主窗口，检查消息列表是否为空、快捷键是否注册成功，并查看窗口底部的状态提示。确认游戏处于前台、聊天框已关闭、修饰键已松开，且发送冷却已结束。快捷键被占用时，到「设置」中换一个按键并保存。

**输入中断或只出现了部分文字怎么办？**

先检查并清理游戏聊天框内残留的文字，关闭聊天框后再重试。主窗口的「下一条」可用于确认当前发送进度。

**如何备份消息，或迁移到另一份程序？**

在「消息管理」中点击「TXT 导出」保存文件，再到目标程序中使用「TXT 导入」。导入会追加到已有列表。

## 项目原理

程序通过 Windows 全局快捷键接收操作，再向前台游戏窗口模拟键盘输入。消息来自用户维护的本地列表，按顺序循环使用；程序不分析聊天内容，也不自动生成回复。

托盘启动时延迟创建主窗口，首次打开设置时再创建设置页；检查更新使用临时子进程，结束后释放其网络资源。隐藏窗口和可见空闲状态停止状态轮询，发送及冷却期间按需刷新。

### 从快捷键到消息发送

```text
F8 / F9（可自定义）
  → Windows 热键消息 → Qt 原生事件过滤器
  → 检查发送锁、冷却、消息列表、游戏前台窗口和修饰键
  → 后台线程打开对应聊天频道 → 输入消息 → 按 Enter
  → 推进共用索引 → 开始共用冷却 → 更新界面状态
```

1. **接收快捷键**：`hotkey.py` 使用 `RegisterHotKey` 注册两个频道的快捷键，由 Qt 原生事件过滤器接收 `WM_HOTKEY`。`MOD_NOREPEAT` 抑制长按重复触发，超过 150ms 的旧热键消息会被丢弃，避免界面阻塞后补执行。
2. **确认输入目标**：`win32_api.py` 获取前台窗口及其进程 ID，再通过 Windows 进程列表核对进程名是否为 `valorant-win64-shipping.exe`。确认后，在本次输入期间持续检查同一窗口和进程是否仍处于前台。
3. **执行输入流程**：`sender.py` 在后台线程中操作键盘，界面继续响应。队伍频道按 Enter 打开聊天；全体频道将 Shift 与 Enter 的按下事件一次提交，保持 80ms，先释放 Enter，再隔 30ms 释放 Shift。等待聊天框打开后输入文本，最后按 Enter 提交。

### 中文和按键如何输入

`win32_api.py` 通过 `ctypes` 调用 Windows `SendInput`。Enter 使用虚拟键码，Shift 使用左 Shift 的扫描码；消息文本则编码为 UTF-16，使用 `KEYEVENTF_UNICODE` 提交每个编码单元的按下和释放事件，因此不需要切换中文输入法或借助剪贴板粘贴。

文本逐字符提交，不额外设置逐字延迟；每个字符输入前检查前台窗口、退出请求及修饰键状态。`SendInput` 返回的事件数少于预期时，会作为异常处理。

### 为什么两个频道不会同时发送

两个频道共用一个 `Sender`、发送锁、忙碌标记和冷却截止时间。发送中或冷却中的触发直接丢弃，不排队；消息编辑和设置保存也会在发送期间受限，避免中途改变正在使用的数据。

只有整段本地输入流程完成后，`MessageManager` 才将索引加一，到列表末尾后回到第一条。发生异常时索引不推进；正常完成和异常中止都会从流程结束时开始计算冷却。异常或退出时，程序会尝试释放本次仍按住的 Enter、Shift 等按键，聊天框中的残留文字需由用户检查和清理。

### 消息与设置如何保存

消息列表保存在 `messages.json`，设置保存在 `config.json`，数据目录见下方「项目结构与开发」。保存时先在同目录写入临时文件、刷新到磁盘，再通过 `os.replace` 替换目标 JSON，减少中途写入失败造成半份文件的风险。读取时会校验内容，遇到损坏或格式不符的文件会报错并保留原文件。

循环索引只保存在内存中，重启程序或修改消息列表后归零。程序还使用数据目录中的 `QLockFile` 防止共用同一数据目录的实例重复启动。

### 能确认到哪一步

当前实现使用前台窗口、进程列表、按键状态和模拟输入接口，不读取游戏进程内存，不向游戏注入代码，也不安装键盘钩子。程序没有聊天框识别、聊天内容读取或服务器送达确认；界面中的「输入流程完成」仅表示本地按键流程执行完毕，所以使用前仍需关闭聊天框，并在输入期间保持游戏在前台。

### 自动检查与性能基线

推送 `main` / `Beta`、向这两个分支提交 PR 或手动运行工作流时，GitHub Actions 会在 Windows / Python 3.11 上执行自动测试、依赖检查、EXE 构建和打包依赖检查，并上传 EXE 与源码、打包版的性能报告。CI 不会自动创建 Release。

本地记录性能基线：

```powershell
.\.venv\Scripts\python.exe -B scripts/performance_baseline.py --output artifacts/performance/baseline.json
.\.venv\Scripts\python.exe -B scripts/performance_baseline.py --baseline artifacts/performance/baseline.json --output artifacts/performance/current.json
```

默认在 3 个独立进程中测量并取中位数，覆盖隐藏初始化、打开窗口和设置、加载与搜索 5000 条消息、导入 1000 条消息，以及连续 3 次更新检查。报告包含各阶段耗时、工作集、私有提交内存和环境、版本、提交及工作区状态。使用 `--executable dist/ValorantToxicTamer-v<完整版本号>.exe` 可测量本次打包产物。

探针使用临时数据和离屏界面，不注册全局快捷键、不模拟按键、不请求网络；更新检查会实际创建子进程并加载网络依赖，再返回固定结果。启动耗时从 Python 入口开始，不含进程创建或单文件 EXE 解压时间。这些是隔离环境下的基线，不能替代真实桌面、在线更新和游戏验证。

仅比较相同 Python、Qt、操作系统及源码/打包模式的报告。可选 `--baseline` 对比中，耗时超过基线的 `1.5 倍 + 100ms`，或内存超过 `1.2 倍 + 8 MiB` 时返回失败并记录差异；阈值用于容忍运行环境波动。CI 每次保留报告供比较，不对不同托管机器的绝对内存或耗时强制设限。
